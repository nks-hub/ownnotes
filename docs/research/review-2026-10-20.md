OwnNotes has a useful local-first foundation, but recovery, account handling, and native share delivery need attention before adding broader features.

Reviewed revision: `688619ff862b5ea6c6b143c1711a4640c49847cc`. Scope included the Flutter app, protocol/store implementation, tests, `TODO.md`, architecture/research documents, and relevant Android/iOS adapters. This is a source review, not a device-test result. No files were changed; the working tree remains clean.

## 1. Code and UX review

Findings are ordered by user impact. “High” covers potential text loss, unintended content changes, privacy failures, or blocked recovery.

### High impact

| # | Finding and consequence | Source |
|---|---|---|
| 1 | **Shared text is consumed before durable import.** Android clears its in-memory slot when Flutter reads it. iOS removes the inbox entry immediately. A crash, failed database write, or interrupted import can therefore lose text that the sending app considers delivered. Android also has only one slot; iOS silently retains only the newest 16 entries and uses an unlocked read–modify–write across processes. Use persistent commands with IDs, acknowledged only after the local transaction commits. | [MainActivity.kt:51](../../apps/mobile/android/app/src/main/kotlin/com/nkshub/nextcloudnotes/MainActivity.kt:51), [ShareInbox.swift:10](../../apps/mobile/ios/Runner/ShareInbox.swift:10), [home.dart:96](../../apps/mobile/lib/features/home.dart:96) |
| 2 | **The app lock can fail open.** After authentication throws, a second failure while checking device support becomes `false`, which grants access. Failure to read preferences also silently applies `lock=false`. Distinguish “the owner removed the device lock” from an unavailable authentication/storage service. | [lock.dart:55](../../apps/mobile/lib/features/lock.dart:55), [data/settings.dart:48](../../apps/mobile/lib/data/settings.dart:48) |
| 3 | **Reauthentication cannot repair an existing account.** The suggested action is “Add the account again,” but onboarding always creates another UUID and credential reference. Existing unsent drafts remain attached to the broken account. Replace credentials on the verified existing identity and preserve its data. | [app_en.arb:64](../../apps/mobile/lib/l10n/app_en.arb:64), [accounts.dart:25](../../packages/notes_store/lib/src/accounts.dart:25), [runtime.dart:57](../../apps/mobile/lib/data/runtime.dart:57) |
| 4 | **An overlapping edit can be combined without asking.** When a pull arrives during unsaved typing, `_adopt()` falls back from a failed three-way merge to `mergeVersions()`, then schedules a save. Two contradictory replacements can become consecutive lines and later upload automatically. This bypasses the explicit comparison used by the recovery screen. | [editor.dart:180](../../apps/mobile/lib/features/editor.dart:180), [recovery.dart:12](../../packages/notes_store/lib/src/recovery.dart:12) |
| 5 | **An open editor does not reliably reflect new permissions or recovery state.** Read-only controls and the decision banner use the original `widget.note`. | 7 | **Failed deletions disappear from all normal recovery surfaces.** `deleting` rows are excluded from the list and export. `_delete()` swallows non-404 HTTP failures and uncertain outcomes without setting the sync problem. Add a visible pending-deletion state, retry reason, and undo/recovery. | [database.dart:123](../../packages/notes_store/lib/src/database.dart:123), [sync.dart:184](../../packages/notes_store/lib/src/sync.dart:184), [settings.dart:95](../../apps/mobile/lib/features/settings.dart:95) |
| 8 | **External entry points do not identify the destination account.** Widget links contain only a local note ID; `_openLink()` searches the currently shown account. After a cold start, that can differ from the widget’s published account. Incoming shares also use the shown/default account without an account chooser. With multiple servers, this can open nothing or save private text to the wrong server. | [NotesWidget.kt:43](../../apps/mobile/android/app/src/main/kotlin/com/nkshub/nextcloudnotes/NotesWidget.kt:43), [home.dart:69](../../apps/mobile/lib/features/home.dart:69), [home.dart:96](../../apps/mobile/lib/features/home.dart:96) |

### Lower impact and consistency

- **Login diagnostics and cancellation:** all failures become one generic message. Cancellation during the initial `start()` request does not stop the subsequently returned session from opening the browser. Check cancellation after each awaited step and expose safe error categories. [login.dart:33](../../apps/mobile/lib/features/login.dart:33), [login.dart:58](../../apps/mobile/lib/features/login.dart:58).
- **Editor usability:** preview links have no `onTapLink`; formatting/list continuation and explicit undo/redo controls are absent. Preview rebuilds lose their scroll position, and incoming text replaces selection with a collapsed cursor and clears composing state. The compact checkbox deliberately reduces its touch target. [editor.dart:204](../../apps/mobile/lib/features/editor.dart:204), [editor.dart:456](../../apps/mobile/lib/features/editor.dart:456), [editor.dart:83](../../apps/mobile/lib/features/editor.dart:83).
- **Settings and localization:** EN/CS ARB message keys are complete, but unsupported locales fall back to the first supported locale, Czech. Face ID’s native explanation remains English. Preference writes can fail silently while switches appear saved. There are no background/Wi-Fi controls or runtime telemetry choice. [app_localizations.dart:96](../../apps/mobile/lib/l10n/app_localizations.dart:96), [Info.plist:11](../../apps/mobile/ios/Runner/Info.plist:11), [data/settings.dart:64](../../apps/mobile/lib/data/settings.dart:64).
- **Collection performance:** every search keystroke scans all cached bodies; an open editor requests an account-wide sync every four seconds. Unchanged full records still receive new local revisions. Measure larger collections before introducing FTS, adaptive polling, or more caching. [home.dart:434](../../apps/mobile/lib/features/home.dart:434), [editor.dart:154](../../apps/mobile/lib/features/editor.dart:154), [database.dart:277](../../packages/notes_store/lib/src/database.dart:277).

The existing strengths should remain: raw Markdown by default, explicit preview, transactional draft saves, partial PUTs with quoted `If-Match`, preservation of edits made during requests, and no automatic replay of an uncertain CREATE.

The documentation needs careful interpretation: [candidate.md:76](../../docs/architecture/candidate.md:76) still lists several implemented features as absent. The newer TODO records progress, while the research document describes acceptance requirements, not proof that all requirements passed.

## 2. Nextcloud API coverage

### Notes REST API v1

CRUD correctly uses `/index.php/apps/notes/api/v1`. Minor capabilities such as `1.4` must not mechanically replace that CRUD base. Notes 6.1 announces API versions `0.2`, `1.3`, and `1.4`, plus the Notes app version and authenticated notes path. OwnNotes reads none of these announcements. [Server capabilities](https://raw.githubusercontent.com/nextcloud/notes/v6.1.0/lib/AppInfo/Capabilities.php), [announced versions](https://raw.githubusercontent.com/nextcloud/notes/v6.1.0/lib/AppInfo/Application.php).

| Capability | OwnNotes coverage | Worth doing |
|---|---|---|
| Version discovery | **Missing.** Neither OCS capabilities nor `X-Notes-API-Versions` is consumed; accounts remain nominally `capabilitiesPending`. | Require a compatible API with concurrency support before enabling writes; explain missing/disabled Notes. |
| CRUD and partial updates | **Present.** Create/read/update/delete; changed-field PUT and conflict response parsing. | Retain the current transport; improve recovery surfaces. [Server controller](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Controller/NotesApiController.php). |
| Per-note ETag | **Present.** JSON ETag protects PUT; conditional detail GET is used before deletion. | Keep Notes ETags separate from DAV file ETags. |
| List `If-None-Match` | **Unused.** List ETag is returned but not consumed; list 304 is treated as an error. | Optional after correctness: cache the exact account/request representation, not a generic account ETag. [API specification](https://raw.githubusercontent.com/nextcloud/notes/main/docs/api/v1.md). |
| `pruneBefore` | **Present, incomplete persistence.** Uses server `Last-Modified`, handles ID-only records, falls back to a full pull for unknown IDs. Watermarks disappear on restart. | Persist only completed, scope-valid watermarks. [sync.dart:133](../../packages/notes_store/lib/src/sync.dart:133). |
| Chunked pull | **Present.** Size 100, opaque cursor, repeated-cursor detection. Pending count is ignored. Census uses the union of all pages instead of the final page’s current membership. | Use final-page IDs; surface initial-sync progress and retain scope/recovery information. The server’s final response includes current membership. [Server listing implementation](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Controller/NotesApiController.php), [pruning implementation](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Controller/Helper.php). |
| Settings | **Missing.** No `GET/PUT /settings`, `notesPath`, or `fileSuffix`. | Read settings first; later expose account-level changes separately from device preferences. Use returned values: current server defaults need not match old documentation. [Settings implementation](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Service/SettingsService.php). |
| Categories | **Partial.** Category strings and `/` descendants work locally; server category filtering is unused. | Build the local tree first. Filtered network listings must never authorize deletion outside their scope. |
| Favorites | **Present at protocol/store level; partial UX.** Offline changes use the outbox, including readonly favorites. | Add Favorites navigation and optional favorites-first sorting. |
| Readonly notes | **Partial.** Initial controls and database guards exist; live permission changes are not reflected correctly. | Use current local state in the editor. The server permits favorite changes on readonly notes. [Note attributes and permissions](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Service/Note.php). |
| Error details / `errorMessage` | **Partial.** HTTP errors retain only status; unreadable notes retain only identity. | Persist a safe error category. Do not assume `errorMessage` always exists: inspected server code returns `errorType`; unreadable note content may itself contain diagnostics. [Error responses](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Controller/Helper.php). |
| Attachments | **Read-only, image-only subset.** GET exists; POST and DELETE are absent. | Add version-aware routes, durable upload phases, returned-path insertion, cache, and verified moves. |
| `modified`, `exclude`, extra metadata | `modified` is read but cannot be supplied on import; `exclude` is unsupported. Server `internalPath`, `isShared`, and `shareTypes` are discarded. | Preserve import dates where useful; retain file/share metadata for later DAV/OCS features. Partial projections require additional models. [API specification](https://raw.githubusercontent.com/nextcloud/notes/main/docs/api/v1.md), [server note representation](https://raw.githubusercontent.com/nextcloud/notes/main/lib/Service/Note.php). |

**Attachment compatibility matters now:** OwnNotes always requests `/api/v1/attachment/{id}`. Notes 6.0.2 exposes GET/POST only under `/api/v1.4/attachment/{id}`; Notes 6.1 adds the `v1` alias and DELETE. API `1.4` alone does not establish the attachment storage/deletion profile. There is no general attachment-list endpoint established by the inspected contract. [6.0.2 routes](https://raw.githubusercontent.com/nextcloud/notes/v6.0.2/appinfo/routes.php), [current routes](https://raw.githubusercontent.com/nextcloud/notes/main/appinfo/routes.php).

The public Notes API also does **not** provide an atomic category-tree rename, reminders, arbitrary labels, idempotent CREATE, or conditional DELETE. Browser-facing Notes routes are not automatically public REST contracts.

## 4. Compatible ideas from competing apps

Colors, arbitrary tags, archive flags, and reminders need an explicit storage convention. They are not standard Notes attributes. Avoid silently introducing metadata that disappears in other clients.

## 5. Note-list redesign

### Compact header and navigation

Use one compact top bar containing **category navigation, current collection/account, search, and overflow**. Move “Add account” into the account menu. Show sync state as a small actionable indicator; expand it into a banner only for actionable failures.

Recommend a list as the default. A grid can be optional later; a permanent horizontal strip of category chips does not scale.

Build a category tree from slash-separated paths:

```text
All notes
Favorites
Uncategorized
Needs attention
Work
  Project
  Meetings
Personal
```

Create virtual parents even when they contain no direct notes. Selecting a parent includes descendants, which the current filter already supports. Show counts, remember expansion per account, and create new notes in the selected category. Empty server folders require DAV; they cannot be inferred from note records.

### Richer rows using current local data

| Row element | Available now? |
|---|---|
| Title, category, favorite, readonly | **Stored directly.** |
| Modification time | **Stored as `updatedAt`**, but it mixes local edit time with server `modified`; separate these before presenting precise server timestamps. |
| Excerpt | **Derivable from content.** Strip display markup and suppress a repeated first-line title without rewriting source. |
| Sync state | **Stored directly.** Join operation error codes for actionable details. |
| Checklist progress | **Derivable**, using a correct Markdown parser and source mapping. |
| Attachment indicator/count | **Derivable references only.** Actual existence, size, download state, and integrity are not stored. |
| Creation date, tags, attachment manifest | **Not currently available as first-class local fields.** |

Suggested row: title and favorite; one or two excerpt lines; a quiet metadata line with category, relative time, and task/attachment indicators. Show explicit **Waiting**, **Sending**, **Needs decision**, or **Pending deletion** where relevant. Use labels and accessibility semantics, not color alone.

### States and tablet behavior

- **No account:** clear “Connect Nextcloud” action.
- **First synchronization:** progress and downloaded count; distinguish this from an empty server.
- **Empty collection:** “Create note,” using the selected category.
- **No search matches:** preserve the query and offer “Clear search.”
- **Offline:** keep cached notes visible; show pending count and last completed sync.
- **Failure:** retain content and provide Retry, Sign in again, or Resolve.
- **Tablet/wide window:** optional category rail, approximately 320–380 dp list pane, remaining editor pane with a readable text width. Preserve editor identity, draft, selection, and scroll across resizing and note changes.
- **Phone:** retain list → editor navigation; collapse title/category metadata while writing. Keep preview an explicit action.
